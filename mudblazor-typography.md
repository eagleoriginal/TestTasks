# Типографика MudBlazor: что куда ставить

Шпаргалка для Adminka. Документация MudBlazor (https://mudblazor.com/components/typography) показывает варианты `Typo`, но не объясняет, зачем каждый нужен. Здесь это объяснение.

## Главная мысль

С отступами всё понятно: `pa-4`, `gap-2` — шаги одной линейки. С текстом устроено так же.
`Typo.*` — это **ступенька готовой лестницы размеров** из Material Design (MudBlazor скопировал значения из MUI).

`Typo` задаёт **роль и внешний вид**, а не HTML-тег. Если по смыслу нужен `<h2>`, а выглядеть он должен как h6:

```razor
<MudText Typo="Typo.h6" HtmlTag="h2">Платёжные реквизиты</MudText>
```

## Вся лестница (значения темы по умолчанию)

| Typo | Размер | Жирность | Высота строки | Для чего задумано |
|---|---|---|---|---|
| h1 | 96px | 300 | 1.167 | Огромный текст на лендинге. В админке не нужен |
| h2 | 60px | 300 | 1.2 | То же |
| h3 | 48px | 400 | 1.167 | Очень крупный заголовок, почти не используется |
| h4 | 34px | 400 | 1.235 | Большая цифра на дашборде («1 284 платежа») |
| **h5** | 24px | 400 | 1.334 | **Заголовок страницы** |
| **h6** | 20px | 500 | 1.6 | **Заголовок карточки или секции** |
| subtitle1 | 16px | 400 | 1.75 | Подзаголовок. В стандартной теме почти не отличается от body1, см. ниже |
| **subtitle2** | 14px | 500 | 1.57 | **Заголовок группы полей внутри карточки** |
| body1 | 16px | 400 | 1.5 | Основной текст, когда его много и его читают (абзацы) |
| **body2** | 14px | 400 | 1.43 | **Основной текст в плотном интерфейсе** (таблицы, карточки) |
| **caption** | 12px | 400 | 1.66 | **Подписи, «метка: значение», даты, подсказки** |
| overline | 12px | 400, КАПС, разрядка | 2.66 | Мелкая надпись над чем-то («СТАТУС») |
| button | 14px | 500, КАПС | 1.75 | Текст внутри кнопки. Вручную почти никогда не нужен |

**В админке нужно 5 ступенек из 13** (выделены жирным).

## Почему с текстом сложнее, чем с отступами

У отступа одно свойство: расстояние. Одно значение `Typo` задаёт сразу три:

1. **Размер.**
2. **Жирность.** h6 и subtitle2 полужирные (500), а body2 того же размера — нет.
3. **Высота строки** (line-height). Из-за неё у текста есть невидимые поля сверху и снизу. Поэтому `mb-2` под текстом выглядит больше, чем `mb-2` под кнопкой. Это нормально.

Четвёртый рычаг — **цвет**. Второстепенный текст выделяют не размером, а бледностью:

```razor
<MudText Typo="Typo.caption" Color="Color.Secondary">Терминал</MudText>
<MudText Typo="Typo.body2">893</MudText>
```

(или `Class="mud-text-secondary"`). Бледная метка caption над значением body2 обычного цвета — это половина всех админок.

## Рецепт для Adminka

```
Страница
 └ h5                        — «Заявка №123»
   Карточка
    └ h6                     — «Платёжные реквизиты»
      subtitle2              — «Шлюз Paygine» (группа внутри карточки)
        caption + secondary  — «Терминал»       ← метка
        body2                — 893              ← значение
      body2                  — обычный текст, пояснения
      caption + secondary    — «создано 12.10.2026, admin»
```

Хороший пример в коде — `Components/Administrate/Requests/RequestCardPage.razor`: там h5 → h6 → body2/caption.

## Правило иерархии

**Пропускать нельзя уровни смысла, а не пункты enum.**

Уровни смысла: заголовок страницы → заголовок секции → заголовок группы → текст → подпись.
Ошибка — когда под заголовком страницы сразу идёт текст секции без её заголовка, или когда заголовок группы крупнее заголовка секции.

13 значений `Typo` — это меню, а не лестница, которую надо пройти целиком. Каждому уровню соответствует одна строчка.

Уровни различаются **размером и жирностью вместе**:

```
h6         20px  полужирный   ← заголовок секции
subtitle2  14px  полужирный   ← заголовок группы
body2      14px  обычный      ← текст
caption    12px  обычный      ← подпись
```

Поэтому скачок h6 20px → subtitle2 14px нормален: subtitle2 того же размера, что и текст, но полужирный, и глаз сразу читает его как заголовок.

Другие правила:
- Иерархия держится на 2–3 соседних уровнях плюс цвет. Если на одном экране h4, h5, h6 и subtitle1 одновременно, это перебор.
- Если понадобился четвёртый уровень заголовков внутри карточки, скорее всего, карточку лучше разбить на две.

## subtitle1 и body1 — почему не видно разницы

В стандартной теме они отличаются только высотой строки:

| | Размер | Жирность | Высота строки | Межбуквенный интервал |
|---|---|---|---|---|
| body1 | 16px | 400 | 1.5 (24px) | 0.15px |
| subtitle1 | 16px | 400 | 1.75 (28px) | 0.15px |

В одной строке текста разницы не видно, заметно только по чуть большему расстоянию до соседей.

Две ступеньки существуют потому, что это **разные роли**, и их можно оформить по-разному через тему. Пока тему не меняли, они выглядят одинаково.

С subtitle2 и body2 иначе: размер одинаковый (14px), но subtitle2 полужирный. Поэтому subtitle2 полезен, а subtitle1 в стандартной теме нет.

Если промежуточный уровень между h6 и subtitle2 всё же нужен, subtitle1 можно сделать отличимым через тему:

```csharp
new MudTheme
{
    Typography = new Typography
    {
        Subtitle1 = new Subtitle1Typography { FontWeight = "500" },
    }
};
```

Тогда он станет полноценным уровнем: 16px, полужирный.

Без правки темы:
- subtitle1 не используй, бери `subtitle2` или `h6`;
- «текст обычный, но заметнее» делай жирностью (`Style="font-weight:500"`) или цветом, а не другим `Typo`.

## Отступы вокруг текста

Ставятся как обычно:
- `Class="mb-2"` и другие классы отступов;
- `<MudStack Spacing="1">` для вертикального списка;
- `GutterBottom="true"` у `MudText` — стандартный отступ снизу под заголовком.

Помни про невидимые поля от line-height: визуально отступ у текста больше, чем указан в классе.
