# Анимации: шесть приводов и два `@keyframes`

Шпаргалка по Angular **22.1.5** (версия из `tehnoinnovalk.client`) и Kendo Angular **25.1.0**.
Все примеры — из этого репозитория, ничего выдуманного: каждая ссылка `файл:строка` открывается
и содержит ровно то, что написано рядом. Документ покрывает оба приложения, клиент и Adminka, —
одна из анимаций живёт именно в админке, а ищут её обычно в клиенте.

Соседние документы (лежат в репозитории [TestTasks](https://github.com/eagleoriginal/TestTasks)):
[angular-render-hooks.md](https://github.com/eagleoriginal/TestTasks/blob/master/angular-render-hooks.md),
[angular-change-detection-zoneless.md](https://github.com/eagleoriginal/TestTasks/blob/master/angular-change-detection-zoneless.md).

## 1. Короткий ответ

Анимаций в клиенте девять штук. Способов их запустить — шесть, и они **не взаимозаменяемы**:
каждый выбран под конкретный момент, в который нужно начать движение.

| Что заставляет анимацию начаться | Чем сделано | Где смотреть |
|---|---|---|
| элемент появился в DOM | `@starting-style` | `user-notifications-button.component.scss:45-53` |
| поле компонента изменилось → атрибут/класс | `@keyframes` + `transition` | `cashboxes-main.component.scss:83-85`, `:128-132` |
| «сыграй прямо сейчас, ещё раз» | WAAPI поверх припаркованной CSS-анимации | `cashboxes-main.component.ts:678-687` |
| «сыграй прямо сейчас», CSS не участвует | `element.animate()` | `reload-buton.component.ts:50-59` |
| координаты приходят с мыши | `Renderer2` + `transition` вручную | `cashboxes-main.component.ts:852-999` |
| вызов из Blazor через JS-interop | reflow-хак + WAAPI | `tehnoinnovaLk.Adminka/wwwroot/js/helpers.js:1-12` |

Плюс седьмой, который никто не писал: Kendo анимирует свои компоненты сам (§9).

Это то, ради чего файл. Остальное — объяснение, почему таблица именно такая, и что делать,
когда понадобится седьмая анимация.

## 2. Ось, которая всё объясняет: эффект и привод — разные вещи

Разнообразия эффектов в клиенте почти нет. Разнообразие — в приводах.

Пересчёт всего, что вообще анимируется, занимает шесть строк:

- `@keyframes dragAnimation` — `cashboxes-main.component.scss:88-102`
- `@keyframes groupPushAnimation` — `cashboxes-main.component.scss:110-126`
- `transition: opacity/transform` на бейдже — `user-notifications-button.component.scss:48`
- `transition: border-color` на цели дропа — `cashboxes-main.component.scss:131`
- `transition: height` на доп. панели — `extra-panel.component.scss:9`
- поворот `<svg>` на 360° — задан прямо в JS, `reload-buton.component.ts:51-54`

Два `@keyframes` и три `transition` на весь клиент. Если бы вопрос был «какие у нас анимации»,
ответ занял бы одно предложение. Ощущение зоопарка возникает не от эффектов, а от того, что
**каждый из них заводится по-своему**.

Причина не в разгильдяйстве, а в том, что CSS умеет реагировать ровно на два события: «значение
свойства изменилось» (`transition`) и «на элементе появилось правило `animation`» (`@keyframes`).
Всё остальное — «сыграй заново то же самое», «сыграй, когда закончится вставка в DOM», «сыграй,
пока пользователь тащит мышь» — в CSS не выражается, и приходится идти в JS. А в Angular «идти
в JS» упирается ещё и в жизненный цикл: до отрисовки элемента его нельзя анимировать, а точка
«отрисовка закончилась» в zoneless-приложении находится не там, где привыкли (§10).

Дальше документ идёт по приводам, от самого дешёвого к самому дорогому. Правило простое:
**бери первый привод сверху, который решает задачу**. Каждый следующий стоит дороже предыдущего,
и §11 сводит это в таблицу.

## 3. Привод 1: элемент появился в DOM

Самый дешёвый из всех — ноль строк TypeScript. Работает, потому что `@starting-style` даёт
браузеру то единственное, чего ему не хватает при вставке узла: значение «до».

Бейдж непрочитанных уведомлений, `user-notifications-button.component.scss:45-53`:

```scss
.badgeEnterAnimation{
  opacity: 1;
  transform: translateY(0);
  transition: opacity 500ms ease-in, transform 500ms ease-in;
  @starting-style {
      opacity: 0;
      transform: translateY(5px);
  }
}
```

Триггером служит обычный `@if` — `user-notifications-button.component.html:7-9`:

```html
@if (hasNotReadedEvents$|async)
{
<kendo-badge class="badgeEnterAnimation" themeColor="warning" ...>
```

`transition` — это интерполяция между двумя вычисленными значениями. У элемента, который только
что вставили в DOM, значения «до» нет: браузер сразу считает `opacity: 1` и начальным, и конечным,
интерполировать нечего, переход не запускается. Это и есть причина, по которой до `@starting-style`
анимации появления делали через `setTimeout(() => el.classList.add(...))` — искусственно разносили
вставку и изменение стиля по разным кадрам.

`@starting-style` описывает это самое «до» декларативно. Никакого JS, никакой гонки с change
detection, ничего не ломается при гидратации.

### Чего эта техника не умеет

**Анимации ухода тут нет и быть не может.** Когда `hasNotReadedEvents$` отдаёт `false`, Angular
удаляет узел немедленно — анимировать уже нечего, элемента нет. Чистым CSS уход решается только
для случая «элемент остаётся в DOM, но переходит в `display: none`», и для этого нужны
`transition-behavior: allow-discrete` и `overlay`. В репозитории нет ни того, ни другого —
`grep -rn "allow-discrete\|overlay:" src/` даёт ноль. И в случае `@if` они бы не помогли:
узел удаляется, а не скрывается.

Вот ровно эту дыру закрывает `animate.leave` в Angular 22 — он заставляет фреймворк дождаться
конца анимации, прежде чем убрать узел (`node_modules/@angular/core/types/core.d.ts:5286-5302`).
Почему это стоит начать использовать — §12.

### Поддержка

`@starting-style` — Chrome 117+, Safari 17.5+, Firefox 129+. Деградация мягкая: в старом браузере
бейдж просто появляется без плавности. Ради одного бейджа этого достаточно; если техника пойдёт
в более заметные места, деградацию стоит проверить осознанно, а не по умолчанию.

## 4. Привод 2: поле компонента изменилось

Второй по дешевизне: анимацию заводит сам Angular, когда переписывает атрибут или класс.
Дальше её надо **снять**, иначе второй раз она не сыграет.

### Атрибут плюс `timer(500)` в роли таймера длительности

Когда кассу перетащили в **раскрытую** группу, её карточка должна пульснуть. Селектор смотрит
на атрибут, `cashboxes-main.component.scss:83-85`:

```scss
&[dragged]{
  animation: dragAnimation 280ms;
}
```

Атрибут вешается по совпадению индекса, `virtual-scroll.component.html:40`:

```html
[attr.dragged]="lastDragCashbox === renderedRange().start + $index?'true':null"
```

А снимается через RxJS, `cashboxes-main.component.ts:753-758`:

```ts
this.lastDragCashbox = dragCashboxId;
let lastDragCashboxMem = dragCashboxId;
timer(500).pipe(takeUntilDestroyed(this.destroyRef)).subscribe(()=>{
 if (lastDragCashboxMem == this.lastDragCashbox)
    this.lastDragCashbox = undefined;
});
```

Тот же блок дословно повторён в `:818-823` — это второй путь дропа, через виртуальный скролл.

Три вещи, которые тут стоит увидеть:

- **`timer(500)` — это длительность анимации, продублированная в TypeScript.** В CSS написано
  `280ms`, в TS — `500`. Связи между числами нет никакой, кроме того, что второе больше первого.
  Поправит кто-нибудь CSS до `600ms` — атрибут снимут посреди анимации, и она оборвётся.
  Единственная причина, по которой это до сих пор не выстрелило, — запас в 220 мс.
- **Проверка `lastDragCashboxMem == this.lastDragCashbox` — защита от гонки**, а не
  перестраховка: если за эти 500 мс перетащили вторую кассу, таймер первой не должен гасить
  подсветку второй. Написано правильно.
- **Сравнивается индекс, а не идентификатор.** `lastDragCashbox` сверяется с абсолютным индексом
  строки в виртуальном списке. Пока список не пересортировали в течение этих 500 мс — работает.

### Класс плюс `transition`

Подсветка группы, над которой висит курсор, устроена проще и без таймеров — класс держится
ровно столько, сколько курсор внутри. `cashboxes-main.component.html:105-107`:

```html
[ngClass]="{
    'drag-entered': !dragCashboxGroup && enteredDrawGroup === cashGroup,
  }"
```

`enteredDrawGroup` ставится и сбрасывается в `handleDragEnter`/`handleDragLeave`
(`cashboxes-main.component.ts:694-700`), CSS — `cashboxes-main.component.scss:128-132`.
`transition`, а не `animation`, выбран правильно: состояние здесь не мгновенное событие,
а промежуток, у которого есть начало и конец.

### Host-биндинг плюс `transition: height`

`app-extra-panel` анимирует собственную высоту через host-биндинг, `extra-panel.component.ts:21-24`:

```ts
host:  {
  '[style.height]': "isOpenExtra? 'max-content !important': 'calc('+ fieldsMinLinesCount + ' * var(--lineHeight, 1.7em) + var(--lineHeight, 1.7em)*.05)'",
  '[style.max-height]': "reduceToMaxContent?'max-content':undefined"
},
```

плюс `transition: height 0.2s ease-in` на `:host` (`extra-panel.component.scss:9`).

Сама конструкция рабочая, и `!important` в биндинге доезжает до элемента — вопреки известному
правилу «через `style.x = ...` важность не выставить». Angular разбирает значение сам,
`_debug_node-chunk.mjs:5149-5153`:

```js
const isImportant = typeof value === 'string' ? value.endsWith('!important') : false;
if (isImportant) {
  value = value.slice(0, -10);
  flags |= RendererStyleFlags2.Important;
}
renderer.setStyle(rNode, prop, value, flags);
```

Дальше `DefaultDomRenderer2` вызывает `el.style.setProperty(prop, value, 'important')`
(`_dom_renderer-chunk.mjs:655-656`) — то есть трёхаргументную форму, которая важность
как раз поддерживает. Так что высота действительно переключается.

**А вот `transition: height` на этой паре значений не срабатывает — ни на раскрытии, ни на
закрытии.** Это проверено в Chrome на точной копии `:host`, а не выведено из спецификации:

| Переход | `getAnimations()` | высота на 100 мс (середина) |
|---|---|---|
| `calc(...)` → `max-content` (как в проекте) | `0` объектов | `232.016px` — конечная сразу |
| `calc(...)` → `200px` (контрольный) | `1` × `CSSTransition:height` | `101.234px` — идёт интерполяция |

Причина в том, что `max-content` — ключевое слово, а не длина, и пары «длина ↔ ключевое слово»
браузер по умолчанию не интерполирует. Объект перехода даже не создаётся: высота меняется
мгновенно, `transition` просто не за что зацепиться.

Лечится это одной строкой в `:host` — `interpolate-size` как раз и разрешает интерполяцию
до ключевых слов:

```scss
:host {
  interpolate-size: allow-keywords;
}
```

С ней тот же замер даёт `1 × CSSTransition:height` и `111.328px` в середине — переход идёт.
Свойство молодое, поддержка по браузерам разная; проверять её надо не по памяти, а
`CSS.supports('interpolate-size', 'allow-keywords')` — в Chrome, на котором делался замер,
возвращает `true`. Где не поддерживается — останется сегодняшнее поведение со скачком,
то есть деградация безопасная.

Альтернативы, если нужна поддержка везде: измерить `scrollHeight` и подставить пиксели (панель
и так уже меряет себя в `afterEveryRender`, `extra-panel.component.ts:64-95`), либо
`grid-template-rows: 0fr → 1fr`, который анимируется честно и без измерений.

## 5. Привод 3: припаркованная CSS-анимация, которую заводят из JS

Приём, который стоит запомнить, потому что он решает главную проблему `@keyframes`: как сыграть
одну и ту же анимацию второй раз, не трогая классы.

Анимация объявлена в CSS и сразу поставлена на паузу — `cashboxes-main.component.scss:104-108`:

```scss
.groupPushAnimation{
 animation: groupPushAnimation 600ms;
 animation-play-state: paused;
 animation-fill-mode: forwards;
}
```

Класс висит на панели **постоянно** и никогда не снимается — `cashboxes-main.component.html:99`:

```html
#ep class="!k-elevation-2 k-rounded-t-md !cursor-auto groupPushAnimation" [title]="cashGroup.name"
```

А запускается всё отсюда — `cashboxes-main.component.ts:676-687`:

```ts
static groupAnimationClass = 'groupPushAnimation';

playAnimation(target: HTMLElement) {
  let targetAnimation = target.getAnimations().find(a => (<CSSAnimation>a).animationName?.endsWith(CashboxesMainComponent.groupAnimationClass));
  if(targetAnimation)
  {
    targetAnimation.currentTime = 0;
    targetAnimation.play();
  }
}
```

Вызовы — `:749-750` и `:815-816`, оба под условием `if (!this.IsCashGroupExpanded(...))`:
касса упала в **свёрнутую** группу, содержимого не видно, поэтому пульсирует сама панель группы.
Это сестра механизма из §4: раскрытая группа → пульс карточки атрибутом, свёрнутая → пульс
панели через WAAPI.

### Что здесь на самом деле происходит

`getAnimations()` возвращает не описания правил, а **живые объекты `Animation`** — те же самые,
что создаёт `element.animate()`. CSS-анимация с точки зрения WAAPI ничем не отличается от
скриптовой, кроме того, что у неё есть `animationName` и она подкласс `CSSAnimation`.
`animation-play-state: paused` означает, что объект создан, но его время не идёт. `currentTime = 0`
перематывает в начало, `play()` снимает с паузы.

Ключевое следствие: **класс трогать не надо вообще**. Ни снимать, ни навешивать, ни ждать кадр,
ни форсировать reflow. Именно поэтому закомментированные `//targetAnimation.finish();` и
`//target.offsetHeight;` (`:682-683`) остались закомментированными — они здесь не нужны,
их автор пробовал старый рецепт и отказался.

### Почему `.endsWith()`, а не `===`

Потому что стили компонента scoped, и SCSS-имя `groupPushAnimation` компилятор превращает в
что-то вроде `_ngcontent-abc-groupPushAnimation`. Сравнивать целиком нельзя — суффикс совпадает,
префикс нет.

Обратная сторона в §13: `find` при промахе возвращает `undefined`, и функция молча ничего не
делает. Ни ошибки, ни варнинга.

### Три способа перезапустить анимацию, и когда какой

| Способ | Что делает | Цена |
|---|---|---|
| `anim.currentTime = 0; anim.play()` | перематывает существующий объект | нужен доступ к объекту, а имя scoped |
| снять класс → `void el.offsetWidth` → навесить | заставляет браузер выкинуть и пересоздать анимацию | синхронный reflow, две записи в DOM |
| `anim.cancel(); anim.play()` | выбрасывает состояние и создаёт заново | `cancel()` сбрасывает `fill`, элемент моргает в исходное |

В клиенте выбран первый — правильно. Второй живёт в админке (§8), потому что там нет объекта,
за который можно ухватиться: `playShake` присваивает `style.animation` строкой и оперирует
элементом, который ей передали из Blazor.

## 6. Привод 4: голый WAAPI, CSS не участвует

Когда анимацию не надо переиспользовать и не надо описывать в теме — её проще задать прямо в JS.

Оборот иконки обновления, `reload-buton.component.ts:50-59`:

```ts
svgelement.animate(
  [
    {['transform']: 'rotate(0deg)'},
    {['transform']: 'rotate(360deg)'}
  ], {
    duration: 600,
    easing: "linear",
    fill: 'forwards',
  }
).onfinish = () => svgelement.style.transform = 'rotate(0deg)';
```

Триггер — не шаблон, а поток: `SelfInitiation` (`:27`), в который пишет и клик по кнопке (`:69-75`),
и внешний `Initiation` (`:31-37`). Поэтому весь блок обёрнут в `afterNextRender({ write: ... })`
внутри `runInInjectionContext` — подробности в §10.

### Чем этот объект отличается от CSS-анимации

Ничем, кроме происхождения. Он попадёт в `getAnimations()` того же элемента — но у него
**нет `animationName`** (это `Animation`, а не `CSSAnimation`), поэтому поиск из §5 его не найдёт.
Если когда-нибудь понадобится перезапускать этот оборот по требованию, ссылку придётся сохранить
в поле — искать по имени нечего.

### `fill: 'forwards'` и `onfinish`, который ничего не меняет

`fill: 'forwards'` означает, что после конца анимация продолжает удерживать конечное значение —
`rotate(360deg)`. Присваивание `svgelement.style.transform = 'rotate(0deg)'` в `onfinish` при этом
визуально не даёт ничего: `360deg` и `0deg` — один и тот же поворот. И, строго говоря, оно бы
не подействовало, даже если бы значения различались: анимации в каскаде стоят выше инлайнового
стиля, пока анимация «в силе».

Практическое следствие — не в этой строке, а в том, чего рядом нет: **ссылка на `Animation`
не сохраняется**, поэтому предыдущий оборот нельзя отменить. Быстрые повторные клики навешивают
на один `<svg>` новые анимации поверх незавершённых. Спецификация описывает автоматическое
вытеснение таких «заменённых» анимаций, и на практике браузер их подчищает, но опираться на это
не стоит. Если понадобится честное поведение — держать `Animation` в поле и вызывать `cancel()`
перед новым запуском.

## 7. Привод 5: `Renderer2` вручную

Самый дорогой привод и единственный, где он оправдан безоговорочно: координаты приходят с мыши,
CSS их не знает.

Драг групп касс — `cashboxes-main.component.ts:832-999`. Механика в трёх точках.

**Старт** (`:869-877`) — анимации выключаются, элемент поднимается над остальными:

```ts
this.currDragTarget = ev.dragTarget;
this.initialPosition = undefined;
this.currentPosition = undefined;
this.renderer.setStyle(this.currDragTarget, 'transition', 'none');
this.renderer.setStyle(this.currDragTarget, "position", 'relative');
this.renderer.addClass(this.currDragTarget, 'z-1000');
```

`transition: none` здесь обязателен: без него панель тащилась бы за курсором с задержкой,
пытаясь интерполировать каждое движение мыши.

**Движение** (`:880-900`) — один `setStyle` на событие, значение считает `getTransform()`
(`:1008-1029`), который заодно зажимает координаты в границы родителя.

**Отпускание** (`:982-998`) — здесь самое интересное:

```ts
afterNextRender(() => {
  this.renderer.removeStyle(this.currDragTarget, "transform");
  this.renderer.removeStyle(this.currDragTarget, "position");
  this.renderer.removeClass(this.currDragTarget, 'z-1000');
  if (this.preventDragRollbackAnimation) {
    this.renderer.removeStyle(this.currDragTarget, "transition");
  } else {
    this.renderer.setStyle(this.currDragTarget, "transition", "transform .3s ease-in-out");
  }
},  {injector: this.injector});
```

### Как читать эту развилку

`preventDragRollbackAnimation` выставляется в `handleDropCashBoxGroup` (`:945-948`):
`true` — по умолчанию, `false` — если индекс не изменился, то есть группу бросили на месте.

- **Группа переехала** (`preventDragRollbackAnimation === true`): `transition` просто снимается.
  Элемент уже стоит на новом месте в DOM, `transform` убран — панель оказывается там, где надо,
  без всякого движения. Анимация отката была бы здесь враньём: элемент никуда не возвращается.
- **Группа осталась на месте** (`false`): ставится `transition: transform .3s ease-in-out`,
  и снятый `transform` доезжает до нуля плавно. Это и есть «откат».

Порядок строк выглядит перевёрнутым — `transform` снимают в `:983`, а `transition` назначают
только в `:992`. Работает потому, что оба вызова происходят синхронно в одном коллбэке, до
следующего пересчёта стилей: браузер сравнивает «до» и «после» один раз, и `transition-property`
берёт из состояния «после».

### Почему `afterNextRender`, а не `setTimeout`

Потому что снимать `transform` можно только после того, как Angular перерисовал список в новом
порядке. Раньше — панель прыгнет на старое место и поедет обратно. `setTimeout(0)` этого не
гарантирует: в zoneless-приложении момент перерисовки к макрозадачам не привязан. `afterNextRender`
— единственная точка, которая по определению наступает после коммита DOM (§10).

`{injector: this.injector}` нужен, потому что вызов идёт из обработчика события, а не из
конструктора, то есть вне контекста инъекции.

## 8. Привод 6, чужой: Blazor и `window.playShake`

Единственная анимация репозитория, которая живёт вне Angular. Искать её в клиенте бесполезно —
её там нет.

`tehnoinnovaLk.Adminka/wwwroot/js/helpers.js:1-12`, файл целиком:

```js
window.playShake = (element) => {
    if (!element) return;

    element.style.animation = "none";
    void element.offsetWidth;
    element.style.animation = "shake_small 0.4s ease-in-out";

    element.getAnimations().forEach((anim) => {
        anim.cancel();
        anim.play();
    });
};
```

Цепочка вызова: `App.razor:23` подключает скрипт → `JsHelpers.cs:15-21` оборачивает его в
`InvokeVoidAsync("playShake", element)` → `Program.cs:92` регистрирует сервис → единственный
потребитель `PartnerLkFiscalEntityEditDialog.razor:541` трясёт поле договора при ошибке валидации.
`@keyframes shake_small` — `wwwroot/css/app.css:150`.

### Зачем `void element.offsetWidth`

Это классический reflow-хак, и он ровно про ту же задачу, что §5: сыграть анимацию второй раз.

Браузер не применяет каждую запись в `style` немедленно — он копит их и пересчитывает стиль один
раз перед отрисовкой. Без промежуточного чтения обе строки, `animation = "none"` и
`animation = "shake_small ..."`, схлопнутся в одну: с точки зрения браузера значение свойства не
менялось, значит и перезапускать нечего. Чтение `offsetWidth` требует актуальной геометрии, то
есть **форсирует пересчёт прямо сейчас** — браузер вынужден зафиксировать промежуточное состояние
«анимации нет», и следующее присваивание становится настоящим изменением.

`void` тут — способ сказать «значение не нужно, важен сам факт чтения», чтобы линтер не удалил
строку как бесполезную.

### Что в этой функции лишнее

Блок с `getAnimations()` — второй способ поверх первого. После переприсваивания `style.animation`
анимация уже стартовала; `cancel()/play()` перезапускает её ещё раз. Хуже того, `forEach` идёт по
**всем** анимациям элемента, а не только по shake: попадётся любая другая — её тоже отменят
и запустят с нуля. Сейчас это безобидно (других анимаций на поле нет), но приём неаккуратный.

В Angular-клиенте reflow-хака нет ни одного — там, где он напрашивался, применили §5.

## 9. Что анимирует Kendo и как это глушат

Довольно много. Это стоит помнить, потому что при уходе с Kendo эти анимации исчезнут вместе
с компонентами, и часть придётся писать заново.

| Что | Где включено | Что даёт |
|---|---|---|
| выезд тоста | `notify-service.ts:56` — `animation: { type: "slide", duration: 200 }` | уведомления |
| раскрытие FAB веером | `cashboxes-main.component.html:71` — `[dialItemAnimation]="{duration: 30, gap: 30}"` | единственный стаггер в проекте, `gap` — задержка между элементами |
| раскрытие панели группы | `cashboxes-main.component.html:122` — `[animation]="!preventDragCashBoxGroupAction"` | штатная анимация, выключенная на время драга |
| попапы дропдаунов и фильтров | `animate: true` в `cashboxes-card.component.html:104`, `marketplace-orders.component.html:136`, ещё семь мест | открытие/закрытие |
| скелетоны, лоадеры, прогрессбары | `@keyframes` из темы, `k-skeleton-wave` и родня | приходят вместе с темой |

Первая строка `[animation]="!preventDragCashBoxGroupAction"` — образцовая: анимацию гасят через
API компонента, ровно на время, когда она мешает, и возвращают обратно.

А вот противоположный пример — `shell-component.component.html:10`:

```html
[class]="'noAnimate'">
```

и `shell-component.component.scss:66-68`:

```scss
.noAnimate{
    transform: translateX(0px) !important;
}
```

Выезд бокового меню Kendo убит не флагом, а `!important`-перебивкой `transform`. Работает,
пока Kendo анимирует drawer именно через `transform` — то есть до ближайшего обновления темы,
которое это поменяет. Правильный путь — свойство `[animation]` у `kendo-drawer`; см. §12.

Ещё одна деталь, важная для вектора ухода: `@progress/kendo-angular-animation` в зависимостях
**нет**, компоненты `<kendo-fade>`/`<kendo-expand>`/`<kendo-slide>` не используются ни разу.
То есть переписывать при миграции придётся только те пять строк из таблицы выше, а не слой
анимаций целиком.

## 10. Zoneless и SSR: где вообще можно трогать DOM

Клиент собран без зон — `app.config.ts:29`, `provideZonelessChangeDetection()`. Для анимаций
из этого следует три вещи.

### `NgZone.onStable` больше не приходит

`provideZonelessChangeDetection()` подставляет `NoopNgZone`, у которого `onStable` не эмитит
никогда. Если где-то в голове живёт рецепт «дождаться `onStable` и запускать анимацию» — он тут
не работает.

Насколько это ощутимо, видно по `utils/render-stable-zone.ts:1-70`: там пришлось написать свою
замену `NgZone`, которая переиспускает `onStable` в хвосте каждой отрисовки, потому что от него
зависит Kendo Grid. Комментарий в файле (`:3-15`) объясняет, почему без этого ломается измерение
высот строк.

Для своего кода вывод простой: **точка «DOM готов» — это `afterNextRender`**, и ничто другое.

### Фазы render-хуков

`afterNextRender` принимает фазу, и для анимаций это не украшение:

- `reload-buton.component.ts:43-44` использует `{ write: ... }` — он только пишет, ничего не меряет.
- `extra-panel.component.ts:64-95` использует `mixedReadWrite` и `read`, потому что меряет
  `getBoundingClientRect()` двух элементов и по результату решает, показывать ли кнопку.
- `cashboxes-main.component.ts:982` вызывает `afterNextRender` без фазы — это `mixedReadWrite`
  по умолчанию, и для трёх `removeStyle` подряд достаточно.

Подробный разбор фаз — в [angular-render-hooks.md](https://github.com/eagleoriginal/TestTasks/blob/master/angular-render-hooks.md).

### Контекст инъекции

Оба места, где анимация запускается из подписки, вынуждены его восстанавливать:
`reload-buton.component.ts:42` оборачивает вызов в `runInInjectionContext(this.injector, ...)`,
`cashboxes-main.component.ts:998` передаёт `{injector: this.injector}`. Формы разные, смысл один:
`afterNextRender` требует инжектора, а из коллбэка `subscribe` он сам не находится.

### На сервере ничего этого не происходит

Render-хуки не выполняются при SSR и prerender — вообще. Поэтому ни одна анимация не участвует
в серверной отрисовке и не может сломать статическую генерацию. `@starting-style` из §3 приезжает
в разметку как обычный CSS и срабатывает уже в браузере, при гидратации. Это, к слову, ещё один
довод в пользу CSS-приводов: они единственные, кому SSR безразличен по построению.

## 11. Что выбирать

| Задача | Инструмент | Не брать |
|---|---|---|
| элемент появился и должен «въехать» | `@starting-style` | `setTimeout` + класс |
| элемент уходит и должен «выехать» | `animate.leave` (§12) | `@if` + надежда |
| состояние держится, пока держится условие | класс + `transition` | `@keyframes` |
| событие произошло, надо мигнуть один раз | атрибут + `@keyframes`, снять по таймеру | `transition` |
| то же самое, но может повториться подряд | `animation-play-state: paused` + `currentTime = 0` | снятие/навешивание класса |
| анимация одноразовая и в тему не просится | `element.animate()` | `@keyframes` ради одного места |
| значения приходят с устройства ввода | `Renderer2` + `transition: none` на время | что угодно декларативное |
| анимирует компонент библиотеки | его собственный API (`[animation]`) | `!important`-перебивка CSS |

Правило, закрывающее большую часть случаев без раздумий: **если момент старта выражается
состоянием — это CSS; если моментом времени — это JS**. «Пока курсор над группой» — состояние.
«В тот миг, когда пришёл ответ сервера» — момент. Первое дешевле второго на порядок.

## 12. Куда двигаться

Вектор один, и он не про то, чтобы всё переписать, а про то, чтобы новые анимации перестали
добавлять седьмой способ.

**Целевой набор, в порядке приоритета:**

1. **CSS по умолчанию** — `transition` и `@keyframes`, как в §3 и §4. Это должно покрывать
   всё, кроме перечисленного ниже.
2. **`animate.enter` / `animate.leave`** для появления и ухода — `core.d.ts:5267-5302`. Это
   штатная замена `@angular/animations` в Angular 22, и она закрывает единственную дыру CSS:
   уход элемента, который Angular удаляет из DOM.
3. **WAAPI** — только там, где нужен перезапуск по требованию, то есть ровно `playAnimation`
   (§5). Один случай на весь клиент, и это правильная пропорция.
4. **`Renderer2`** — только драг (§7), где координаты приходят с мыши.

**Что выпилить, от дешёвого к рискованному:**

- **`provideAnimations()` в `app.config.ts:35`.** В проекте нет ни одного `trigger()`, `state()`,
  `animate()` или `[@anim]` — проверено `grep`. Провайдер тянет движок анимаций ради ничего,
  а сам `@angular/animations` помечен deprecated (`package-lock.json:181`). Убирается вместе
  с зависимостью из `package.json:22`; проверить надо только Kendo — он единственный, кто мог
  бы этот движок запросить.
- **`.noAnimate` в `shell-component.component.scss:66-68`** — заменить на штатное свойство
  `kendo-drawer`, которое отключает анимацию. Перебивка `transform` через `!important`
  сломается от обновления темы молча.
- **`timer(500)` в `cashboxes-main.component.ts:755` и `:820`** — дублирование длительности,
  разъезжающееся с CSS (§4, §13). После перехода на `animate.leave`/`animate.enter` таймер
  не нужен вовсе: фреймворк сам знает, когда анимация закончилась.
- **`prefers-reduced-motion`** — сейчас его нет во всём репозитории, ноль вхождений. Это одна
  медиа-обёртка на четыре анимации, дешевле уже не будет:

  ```scss
  @media (prefers-reduced-motion: reduce) {
    .badgeEnterAnimation, .groupPushAnimation, [dragged] { animation: none; transition: none; }
  }
  ```

  Для WAAPI и `Renderer2` то же самое читается через `matchMedia('(prefers-reduced-motion: reduce)')`.
- **`interpolate-size: allow-keywords` на `:host` у `app-extra-panel`** — одна строка, которая
  оживляет уже написанный `transition: height` (§4). Самый дешёвый пункт в этом списке: код
  менять не надо вообще, там уже всё готово, не хватает только разрешения интерполировать.
- **Продублированные длительности** — вынести `--anim-fast: 280ms` и родню в переменные там же,
  где живут остальные токены. Сейчас все числа (`280ms`, `600ms`, `.3s`, `500ms`, `0.2s`)
  вписаны литералами в пяти разных файлах.

**Про уход с Kendo.** Всё перечисленное в §9 — тост, FAB, панель группы, попапы, drawer — придётся
переписать руками в любом случае, каким бы ни был целевой набор компонентов. Хорошая новость
в том, что это ровно пять строк: `@progress/kendo-angular-animation` не используется, отдельного
слоя анимаций поверх Kendo в проекте нет.

## 13. Грабли

- **`playAnimation` промахивается молча.** `cashboxes-main.component.ts:679` ищет анимацию по
  `.endsWith('groupPushAnimation')` среди `getAnimations()`. Переименуют класс, вынесут
  `@keyframes` в глобальный стиль, отключат scoped-стили у компонента — `find` вернёт `undefined`,
  `if` не сработает, и всё. Ни ошибки, ни варнинга: анимация просто перестанет играть, и никто
  не свяжет это с правкой в CSS.

- **`timer(500)` и `animation: 280ms` ничем не связаны.** `cashboxes-main.component.ts:755` и
  `:820` против `cashboxes-main.component.scss:84`. Числа живут в разных файлах и разных языках;
  сегодня их спасает запас в 220 мс. Увеличат длительность в CSS — атрибут снимут посреди
  анимации, и она оборвётся на середине.

- **`transition: transform .3s ease-in-out` остаётся на элементе инлайном.**
  `cashboxes-main.component.ts:992-996`: в ветке «группу бросили на месте» стиль назначается и
  больше не снимается — противоположная ветка (`:987-990`) его не касается. Перезапишется он
  только при следующем драге, в `:872`. Сейчас безобидно, потому что `transform` этой панели
  никто, кроме драга, не трогает; станет заметно, если появится второй источник трансформаций.

- **Оборот иконки нельзя отменить.** `reload-buton.component.ts:50-59` не сохраняет `Animation`,
  поэтому быстрые повторные клики навешивают новые анимации поверх незавершённых. Визуально
  сходит с рук, потому что `360deg` и `0deg` — один и тот же угол.

- **`playShake` бьёт по всем анимациям элемента.** `helpers.js:8-11` вызывает `cancel()/play()`
  в `forEach` по `getAnimations()` без всякой фильтрации. Пока на поле договора нет других
  анимаций — работает; появится вторая, и её перезапустят вместе с тряской.

- **`.shake-effect` в админке мёртв.** `tehnoinnovaLk.Adminka/wwwroot/css/app.css:164-165`:

  ```css
  .shake-effect {
      animation: shake 0.4s ease-in-out;
  }
  ```

  Керфреймов с именем `shake` не существует — единственный объявленный называется `shake_small`
  (`:150`). Класс никуда не подключён (`grep -rn "shake" tehnoinnovaLk.Adminka` находит только
  само объявление и `helpers.js`), поэтому неработающим его никто не заметил. Тряска работает
  исключительно через `playShake`, который подставляет правильное имя строкой в `helpers.js:6`.
  Класс надо либо починить, либо удалить — сейчас он выглядит как рабочий способ и им не является.
