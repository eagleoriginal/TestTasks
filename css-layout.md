# Разметка: flex и grid

## Что выбирать

Отличаются не числом осей — **grid прекрасно работает и в одну строку**. Отличается то,
**кто задаёт размеры**:

| | flex | grid |
|---|---|---|
| Размеры диктует | контент; контейнер делит остаток | контейнер; треки объявлены заранее |
| Число элементов | может быть любым, заранее неизвестным | обычно известно, либо `auto-fit` |
| Несколько строк | каждая живёт сама по себе, колонки не совпадают | треки сквозные, всё выстраивается по одним линиям |
| Позиция элемента | зависит от соседей | задаётся явно: `grid-column`, `grid-area` |

**Grid в одну строку** — нормально и часто лучше flex:

```css
grid-template-columns: 200px 1fr auto;   /* точные треки; flex так не умеет */
grid-auto-flow: column;                  /* колонки под неизвестное число элементов */
```

Бери его, когда нужны **точные размеры колонок**, когда несколько разных строк должны
выровняться по одним и тем же колонкам, или когда позиция элемента не должна зависеть
от того, что лежит рядом.

Бери flex, когда размеры должны определяться содержимым, когда элементов заранее
неизвестное число и они разной ширины с переносом, или когда нужно прижать
что-то к краю через `margin-left: auto`.

Вкладывать свободно: grid для каркаса, flex внутри ячеек.

# FLEX

## Грамматика

```
display: flex                       контейнер; прямые дети становятся флекс-элементами
│
├─ НА КОНТЕЙНЕРЕ
│  ├─ flex-direction: row | column | row-reverse | column-reverse
│  │                                задаёт ГЛАВНУЮ ось; поперечная — всегда другая
│  ├─ flex-wrap:      nowrap | wrap        по умолчанию nowrap — сжимает, не переносит
│  ├─ justify-content: …            вдоль ГЛАВНОЙ оси
│  ├─ align-items:     …            поперёк, каждый элемент
│  ├─ align-content:   …            поперёк, ряды целиком — работает ТОЛЬКО при wrap
│  └─ gap: 12px | 12px 24px         промежутки; margin-хаки не нужны
│
└─ НА ЭЛЕМЕНТЕ
   ├─ flex: <grow> <shrink> <basis>  почти всегда пишут сокращением, см. ниже
   ├─ align-self: …                 перебить align-items для одного элемента
   ├─ order: <число>                визуальный порядок, DOM не меняется
   └─ margin-left: auto             съесть всё свободное место слева → прижать вправо
```

## Оси — единственное, что надо помнить

```
justify-*  →  вдоль ГЛАВНОЙ оси   (той, что задана flex-direction)
align-*    →  поперёк
```

При `flex-direction: column` они меняются местами: `justify-content` управляет
вертикалью, `align-items` — горизонталью.

Значения `justify-content`: `flex-start` `center` `flex-end` `space-between`
`space-around` `space-evenly`.
Значения `align-items`: `stretch` (по умолчанию) `flex-start` `center` `flex-end` `baseline`.

`stretch` по умолчанию — вот почему соседние карточки сами получают одинаковую высоту.

## `flex: …` — во что разворачивается

| Запись | grow | shrink | basis | Смысл |
|---|---|---|---|---|
| `flex: 1` | 1 | 1 | `0%` | **равные доли**, контент не учитывается |
| `flex: auto` | 1 | 1 | `auto` | растёт, но стартует от размера контента |
| `flex: initial` | 0 | 1 | `auto` | значение по умолчанию: не растёт, сжимается |
| `flex: none` | 0 | 0 | `auto` | жёсткий размер, не трогать |
| `flex: 0 0 240px` | 0 | 0 | `240px` | фиксированная колонка |

Разница `flex: 1` и `flex: auto` — единственное, что реально путают: с `basis: 0` колонки
получаются **равными**, с `basis: auto` — пропорциональными длине содержимого.

### `min-width: auto` — где на самом деле пол сжатия

По умолчанию у флекс-элемента `min-width: auto`, и это **не 0**. Он не даёт элементу
сжаться меньше «content-based minimum» — грубо, самого длинного неразрывного слова
или неделимого куска контента. Отсюда вся классика с распираемой таблицей (см. «Ловушки»).

Но пол считается не всегда одинаково — зависит от `basis`:

| `flex-basis` | Что берётся за «свой» размер | Пол сжатия (`min-width:auto`) |
|---|---|---|
| `0%` (как в `flex: 1`) | 0 — **но только если ширина самого flex-контейнера definite** | если контейнер definite → пол = 0, элемент реально схлопывается под контент; если контейнер сам `auto`-ширины (вложенный флекс/грид без явной ширины) → пол = как у `auto` |
| `auto` (как в `flex: auto` / `initial`) | явный `width`, если задан; иначе ничего | пол = content-based minimum, ниже не сожмётся |
| `<length>` (`flex-basis: 50px`) | `50px` | пол = `min(50px, content-min)` — если `50px` меньше контента, элемент СМОЖЕТ сжаться ниже своего содержимого, и оно вылезет |

Практический вывод: `flex: 1` избавляет от пола только когда браузер уверен в ширине
самого контейнера — во вложенных раскладках это часто не так. Надёжно — не полагаться
на `basis`, а явно ставить `min-width: 0` (или любое конкретное значение): явный
`min-width` полностью отменяет автоматический пол, независимо от `basis`.

### `width` / `min-width` / `max-width` против `flex-basis` — кто кого

Это два **разных, последовательных клэмпа**, и «где зарезервировано место» и «какого
размера получился блок» — разные величины именно потому, что второй клэмп срабатывает
позже первого, уже после того как растянуто/сжато.

**Этап 0 — что вообще берётся за стартовый размер (до всякого min/max):**

| Задано | Стартовый размер (`flex base size`) |
|---|---|
| `flex-basis: <length>` | эта длина; **`width` на этом же элементе полностью игнорируется** |
| `flex-basis: auto` + задан `width` | значение `width` |
| `flex-basis: auto`, `width` не задан | размер по контенту |

`flex-basis` **выигрывает у `width` безоговорочно**, если он не `auto`. Не «смешивается»,
не «усредняется» — `width` в этом случае просто не читается вообще, пока элемент во flex.

**Этап 1 — клэмп ДО распределения свободного места (это и есть «резервирование»):**

```
hypothetical main size = clamp(min-width, flex base size, max-width)
```

Именно эта величина суммируется по всем элементам строки и сравнивается с шириной
контейнера — то есть **именно она решает, поместится ли элемент на строку** (перенос
из раздела ниже) и именно с неё стартует grow/shrink. `min-width`/`max-width` тут уже
участвуют, даже если растягивания ещё не было.

**Этап 2 — клэмп ПОСЛЕ распределения (тот самый источник «размер разъехался с резервом»):**

grow/shrink считается от значения этапа 1. Если результат вылезает за `min`/`max` —
элемент **замораживается** на границе, а весь излишек/недостаток, который должен был
достаться ему, **перераспределяется на остальных**, не замороженных, элементов строки.
Значит:

- сосед с `max-width` перестаёт расти раньше остальных → **они дорастают больше**, чем
  давал бы их голый `flex-grow`;
- сосед с `min-width` перестаёт сжиматься раньше остальных → **они сжимаются сильнее**,
  чем давал бы их голый `flex-shrink`.

То есть финальный размер блока — это не «резерв плюс своя доля», а результат ещё одного
раунда дележа, в котором чужой `min`/`max` меняет то, что достаётся тебе.

Ось, к которой это всё относится, зависит от `flex-direction`: в `row` это
`width`/`min-width`/`max-width`, в `column` — `height`/`min-height`/`max-height`.
Свойства на другой (поперечной) оси в этой механике не участвуют вообще — там обычное
поведение блока (`align-items`/`align-self`).

### Перенос строки — это порядок, а не гибкость

`flex-wrap` не выбирает «самый гибкий» элемент для переноса. Алгоритм идёт по **DOM-порядку**
и копит **гипотетический размер** каждого элемента (это `flex-basis`, ДО применения
grow/shrink) слева направо. Как только очередной элемент не влезает в остаток строки —
он и всё, что после него, уходят на новую строку. Поэтому `flex-shrink` сам по себе
**не выталкивает** соседей: сжимающийся разделитель просто ужимается на месте, пока может,
и с обычным `flex-wrap` последний элемент остаётся на той же строке, покуда его
собственный гипотетический размер туда помещается.

Чтобы гарантированно перенести конкретный элемент на новую строку (не полагаясь на то,
что арифметика когда-нибудь сама сложится) — приём «flex line break»: элемент с
`flex-basis: 100%` не может делить строку ни с кем, потому что 100% ширины контейнера
занимает целиком. Он гарантированно уходит на свою строку, а всё, что идёт следом за
ним в DOM — на строку ещё ниже.

```css
.spacer-break { flex-basis: 100%; height: 0; }   /* сам невидим, но рвёт строку пополам */
```

Если между строками стоит `gap`, он всё равно вставится сверху и снизу этой невидимой
строки — заложи это в расчёт высоты, либо разводи строки через `margin`, а не `gap`.

# GRID

## Грамматика

```
display: grid
│
├─ ОПРЕДЕЛЕНИЕ ТРЕКОВ
│  ├─ grid-template-columns: 200px 1fr 200px      три колонки
│  ├─ grid-template-rows:    auto 1fr auto        шапка / резина / подвал
│  ├─ grid-template-areas:   "hd hd" "sb mn"      именованный каркас
│  ├─ grid-auto-rows: minmax(80px, auto)          размер НЕявных рядов
│  └─ grid-auto-flow: row | column | dense        куда класть то, что не разместили
│
├─ ФУНКЦИИ РАЗМЕРА
│  ├─ 1fr                     доля СВОБОДНОГО места (не доля контейнера)
│  ├─ minmax(200px, 1fr)      от и до
│  ├─ repeat(3, 1fr)          повтор
│  ├─ repeat(auto-fit, …)     столько колонок, сколько влезет
│  ├─ min-content/max-content по содержимому
│  └─ auto                    как max-content, но растягивается остатком
│
├─ РАЗМЕЩЕНИЕ ЭЛЕМЕНТА
│  ├─ grid-column: 1 / 3          с первой линии по третью
│  ├─ grid-column: span 2         занять две колонки от текущего места
│  ├─ grid-column: 1 / -1         на всю ширину (-1 = последняя линия)
│  └─ grid-area: hd               в именованную область
│
└─ ВЫРАВНИВАНИЕ
   ├─ justify-items / justify-content    по горизонтали (inline-ось)
   ├─ align-items   / align-content      по вертикали (block-ось)
   ├─ place-items: center                = align-items + justify-items
   └─ justify-self / align-self          для одного элемента
```

`-items` — содержимое **внутри ячейки**. `-content` — сама **сетка внутри контейнера**,
имеет смысл только когда треки меньше контейнера.

## `auto-fit` vs `auto-fill`

```css
grid-template-columns: repeat(auto-fit,  minmax(220px, 1fr));   /* пустые треки схлопываются */
grid-template-columns: repeat(auto-fill, minmax(220px, 1fr));   /* пустые треки остаются */
```

Адаптивная сетка карточек без единого медиазапроса — это `auto-fit` + `minmax`.
Разница между ними видна только когда элементов меньше, чем помещается колонок:
`auto-fit` растянет их на всю ширину, `auto-fill` оставит пустые места.

Чего `auto-fit` **не умеет** — задать конкретные шаги. Число колонок он считает из
доступной ширины, поэтому при сжатии экрана обязательно пройдёт через все промежуточные
значения: 4 → 3 → 2 → 1. Нужно ровно 4 → 2 → 1 — это медиазапросы или `@container`
(рецепты ниже).

# Ловушки

| Симптом | Причина | Лечение |
|---|---|---|
| Длинный текст / таблица распирает флекс-элемент, `overflow` не работает | у флекс-элемента `min-width: auto`, он не сжимается меньше контента | `min-width: 0` на элемент |
| То же в grid-колонке `1fr` | `1fr` = `minmax(auto, 1fr)` | `minmax(0, 1fr)` |
| `height: 100%` игнорируется | у родителя высота `auto` | цепочка `height` до корня, или `100dvh`, или `1fr` в grid-ряду |
| Элементы не переносятся, а сжимаются в кашу | `flex-wrap: nowrap` по умолчанию | `flex-wrap: wrap` |
| `align-content` ничего не делает | ряд один | работает только при `wrap` и нескольких рядах |
| Колонки неравные, хотя у всех `flex: auto` | `basis: auto` считает контент | `flex: 1` |
| Картинка растянулась по высоте | `align-items: stretch` по умолчанию | `align-self: flex-start` или задать `object-fit` |
| Лишняя прокрутка на 100vh | `100vh` не учитывает панель браузера на мобиле | `100dvh` |
| `z-index` будто не работает у ребёнка flex/grid | ложная тревога: у ПРЯМЫХ детей flex/grid z-index работает и без `position` (спека — исключение) | если реально не работает — это внук, не прямой child: там обычное правило, нужен `position` |
| Скачет высота при подгрузке | нет резерва под контент | `aspect-ratio`, `min-height` |

# Рецепты

```css
/* центр по обеим осям */
.box { display: grid; place-items: center; }

/* шапка + контент-резина + подвал на всю высоту экрана */
.app { display: grid; grid-template-rows: auto 1fr auto; min-height: 100dvh; }

/* фикс-сайдбар + резиновый контент */
.layout { display: grid; grid-template-columns: 240px minmax(0, 1fr); }

/* карточки: число колонок выбирает браузер, шаги произвольные (4-3-2-1) */
.cards { display: grid; gap: 16px; grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)); }

/* карточки: ровно 4 -> 2 -> 1, без промежуточной тройки — через медиазапросы */
.cards { display: grid; gap: 16px; grid-template-columns: repeat(4, minmax(0, 1fr)); }
@media (max-width: 1100px) { .cards { grid-template-columns: repeat(2, minmax(0, 1fr)); } }
@media (max-width:  640px) { .cards { grid-template-columns: 1fr; } }

/* то же, но по ширине КОНТЕЙНЕРА — компонент можно вставить куда угодно */
.wrap  { container-type: inline-size; }
.cards { display: grid; gap: 16px; grid-template-columns: repeat(4, minmax(0, 1fr)); }
@container (max-width: 1100px) { .cards { grid-template-columns: repeat(2, minmax(0, 1fr)); } }
@container (max-width:  640px) { .cards { grid-template-columns: 1fr; } }

/* тулбар: слева группа, справа группа */
.bar { display: flex; gap: 8px; align-items: center; }
.bar .spacer { margin-left: auto; }

/* иконка фикс + текст резина, текст обрезается многоточием */
.row { display: flex; gap: 8px; align-items: center; }
.row .icon { flex: none; }
.row .text { flex: 1; min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }

/* равные колонки независимо от содержимого */
.cols { display: flex; gap: 16px; }
.cols > * { flex: 1; min-width: 0; }

/* таблица-сетка: подпись по контенту, значение резиной */
.form { display: grid; grid-template-columns: max-content minmax(0, 1fr); gap: 8px 16px; }

/* растянуть элемент на всю ширину сетки */
.full { grid-column: 1 / -1; }

/* прижать подвал вниз, если контента мало */
.page { display: flex; flex-direction: column; min-height: 100dvh; }
.page main { flex: 1; }
```

# Что ещё есть

| Свойство | Зачем |
|---|---|
| `subgrid` | вложенная сетка выравнивается по трекам родителя — колонки карточек совпадают |
| `aspect-ratio: 16/9` | резерв места под медиа, убирает скачки |
| `container-type: inline-size` + `@container` | адаптив по ширине контейнера, а не экрана |
| `position: sticky; top: 0` | липкая шапка внутри прокручиваемого блока |
| `overflow: auto` + `min-height: 0` | скролл внутри flex/grid-ячейки (без `min-height` не заработает) |
| `order` | переставить визуально, не трогая DOM и порядок табуляции |
| `gap` в flex | поддерживается везде, старые `margin`-хаки не нужны |

# Картинки

`<img>` — не самая простая вещь именно потому, что это разом три независимых слоя:
чем он является в потоке (inline), как заполняет свой бокс (`object-fit`) и что резервирует
место под него до загрузки (`aspect-ratio` / атрибуты). Строка `aspect-ratio: 16/9` из
таблицы выше и `object-fit` из «Ловушек» — это первая цифра этого раздела в одну строку.

## `<img>` — inline-элемент, и почему под ним щель

```
display: inline    ← это НЕ переопределено в UA-стиле, img остаётся строчным
```

Отсюда классика: `<img>` внутри `<div>` без явной высоты у div даёт снизу лишнюю
щель ~4px. Причина: `inline` выравнивается по baseline строки, как обычный символ —
с местом под несуществующий «хвост» (descender), которого у картинки нет.

Три равноценных фикса:

```css
img { display: block; }             /* самый надёжный — просто выходит из этой истории */
img { vertical-align: middle; }     /* или bottom/top — убирает привязку к baseline */
.wrap { line-height: 0; }           /* родителю нечего резервировать под descender */
```

Если картинка не должна течь посреди текста — сразу `display: block` (или
`inline-block`, если нужно обтекание текстом абзаца), и вопрос закрыт раз и навсегда.

## `object-fit` — как картинка заполняет СВОЙ бокс

Работает только когда у `<img>` есть явный размер (CSS или HTML-атрибуты
`width`/`height`), отличный от натурального — иначе рисовать просто нечего иначе.

| Значение | Пропорции | Что видно | Как называть человеку |
|---|---|---|---|
| `fill` (по умолчанию) | **искажает** | всё, но растянуто/сплющено | «просто тянет» |
| `contain` | сохранены | весь кадр целиком | «письма-ящик», по бокам/сверху пустота |
| `cover` | сохранены | обрезано по краям | «заполнить и обрезать» |
| `none` | сохранены | натуральный размер, бокс игнорируется | «как есть» |
| `scale-down` | сохранены | меньшее из `none` и `contain` | «не увеличивать, если и так мало» |

Важная деталь, которую легко упустить: **обрезка `cover` происходит внутри собственного
бокса `img`** — обёртка с `overflow: hidden` не нужна. Это отличает `object-fit` от
старого трюка `background-size: cover` на `div`, которому `overflow` действительно был
нужен (там фон мог вылезти за пределы блока, а `object-fit` клипует сам себя).

## `object-position` — куда именно обрезать или прижимать

По умолчанию `50% 50%` (центр). Синтаксис как у `background-position` — проценты,
ключевые слова, можно смещать к краю:

```css
img { object-fit: cover; object-position: top; }   /* портрет — не срезать голову */
img { object-fit: cover; object-position: 20% 50%; }   /* сместить точку интереса влево */
```

## `aspect-ratio` — резерв места и своя пропорция

Если задать только `width: 100%` без `aspect-ratio` и без `height` — высота посчитается
по натуральному соотношению самой картинки, ничего искажать не будет.

```css
img { aspect-ratio: 16/9; width: 100%; object-fit: cover; }
```

Эта пара навязывает **свою** пропорцию, которая может не совпадать с натуральной —
поэтому `object-fit: cover` тут обязателен, иначе будет заметное искажение.

Отдельно и надёжнее (без единой строчки CSS): проставить `width`/`height` как HTML-**атрибуты**
на `<img>` — браузер выведет из них `aspect-ratio` сам, ещё до того как файл скачается,
и зарезервирует место заранее (это и есть современная замена старому
`padding-bottom: 56.25%`-трюку):

```html
<img src="hero.jpg" width="1600" height="900" style="width:100%; height:auto;">
```

## Фон вместо `<img>` — когда так лучше

Тот же визуальный эффект (`cover`/`contain`/позиция) можно получить и на фоне блока —
без настоящего `<img>` в разметке:

```css
.hero { background: url(hero.jpg) center/cover no-repeat; }
```

| | `<img>` + `object-fit` | `background-image` + `background-size` |
|---|---|---|
| Картинка — это контент | да: `alt`, ленивая загрузка, `<picture>`/`srcset` под разные экраны | нет — для CSS её не существует |
| Поверх нужен текст/оверлей | сложнее (нужен отдельный слой) | естественно — просто контент поверх фона |
| Декоративная картинка | избыточно | то, для чего и придумано |

## Рецепты

```css
/* круглый аватар с обрезкой под квадрат */
.avatar { width: 48px; height: 48px; border-radius: 50%; overflow: hidden; }
.avatar img { width: 100%; height: 100%; object-fit: cover; display: block; }

/* hero-баннер на всю ширину, без искажений, без щели снизу */
.hero img { width: 100%; aspect-ratio: 16/9; object-fit: cover; display: block; }

/* логотип на цветной подложке — не обрезать, вписать целиком */
.badge { width: 120px; height: 120px; background: #f2f2f2; display: grid; place-items: center; }
.badge img { max-width: 80%; max-height: 80%; object-fit: contain; }

/* адаптивная картинка без CLS: атрибуты в HTML держат пропорцию до загрузки */
img { max-width: 100%; height: auto; display: block; }
/* <img src="..." width="1600" height="900" alt="..."> */
```
